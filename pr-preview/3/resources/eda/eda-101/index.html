EDA 101

从规格到 Tapeout：设计环节、主要产物、开源与商业软件，以及真实界面和演示。

做 AI4Chip，先要知道模型改动的对象是什么、工具如何检查它、结果会影响后面的哪个环节。这一页以数字 ASIC 为主线，把设计流程、软件和产物放在一起；模拟电路另列一条入门路径。

从 Specification 到 Tapeout

查看完整尺寸

图中列出各环节的常用软件。OpenROAD 负责物理实现；OpenROAD Flow Scripts 和 OpenLane 将多个工具连接成可运行的流程。Genus、Innovus、Fusion Compiler 等商业工具也会跨阶段协同，实际工程会根据工艺、IP 和团队配置选择工具组合。工具入口见 Open Source 和 Closed Source。

环节主要输入 → 产物看结果时关注什么
Specification / Architecture / MicroarchitectureWorkload、接口和性能目标 → 模块划分、流水线、存储层次与时序约定设计是否满足目标；吞吐、延迟、带宽和资源预算如何分配
RTL & Verification规格 → RTL、testbench、断言、波形和测试报告行为是否正确；复位、边界条件和协议是否覆盖；失败出在哪个周期
SynthesisRTL、标准单元库、SDC 约束 → Gate-level netlist 和初步 PPA 报告逻辑映射成了哪些单元；面积与时序是否满足约束；功能是否保持
FloorplanNetlist、宏单元和工艺信息 → 芯核尺寸、宏单元／引脚位置、电源规划模块是否放得下；连接是否合理；哪里可能拥塞
Placement → CTS (Clock Tree Synthesis) → RoutingFloorplan → 单元位置 → 时钟树 → 金属连线单元放在哪里；时钟如何分发；连线对时序、拥塞和功耗有什么影响
Signoff → Tapeout布线版图、提取的寄生参数和约束 → 检查报告、最终 GDSII / OASIS 及交付文件STA、功耗／电源完整性、DRC、LVS 等是否满足项目和工艺要求

Verification 贯穿整个流程。 RTL 仿真、形式验证、综合网表的等价性检查各有作用；STA (Static Timing Analysis) 从综合阶段就会参与优化。DRC (Design Rule Checking) 检查版图是否符合工艺规则，LVS (Layout Versus Schematic) 检查版图提取的电路是否与参考网表一致，两者都是物理签核的一部分。后期的时序、拥塞或功耗问题，也可能要求回头修改 RTL 或架构。

实际 SoC 还包含 IP 集成、DFT、低功耗设计等工作。下方的 Flow Diagrams 分别给出开源工具链、工业设计流程和端到端 benchmark 的视角。

软件、PDK 和设计文件如何配合

EDA 软件执行仿真、综合或布局布线；PDK 提供工艺模型、层定义与规则，标准单元库提供可映射的单元及其时序、功耗和物理信息。设计还需要时钟、输入输出延迟等约束。同一份 RTL，换了工艺、库或约束，得到的 PPA 也会改变。

初次运行流程时，先找到这几类文件即可：.v / .sv 是设计或 testbench，.sdc 描述时序约束，.lib 描述单元特性，LEF / DEF 表达物理抽象与设计布局，SPEF 保存提取的寄生参数，GDSII / OASIS 保存版图几何。ORFS 还用 ODB 保存可重新打开的设计数据库。ORFS 官方教程把这些输入、目录和中间结果串在了一起。

真实界面：工程师在看什么

下面几张真实界面分别对应调试、物理实现和物理验证。先认出每个窗口处理的设计对象，再看如何从报告定位问题。

Synopsys Verdi · RTL Debug

左侧是设计层次，中间是源码，右侧是电路连接，下方是波形。先找到出错的时钟周期，再把信号值对应回源码与相关模块。

Cadence Innovus · Physical Implementation

中央显示布局与金属连线，右侧控制单元、网络和各图层的可见性。先看芯核边界与模块分布，再逐层查看连线，理解 RTL 最终如何变成版图。

OpenROAD · Physical Implementation

这是 Ibex 设计的布线结果：左侧为图层控制，右侧为设计层次，底部为 Tcl 控制台。运行 ORFS 后打开保存的设计数据库，可以在同一界面中检查布局、连线和时序路径。

Siemens Calibre RVE · Physical Verification

这个例子展示井连接 soft check 的结果。左侧列出检查项与涉及的单元，右侧提供结果详情和坐标；工程师据此回到版图定位连接问题。

想继续看实际操作，可以选择 OpenROAD 的 GUI / CTS / Routing 演示，或 Questa AutoCheck 的形式检查演示。

从脚本到 GUI

GUI 常用来理解设计和定位问题，脚本则负责可重复地运行流程。一个典型操作顺序是：

  1. 用配置和 Tcl 脚本加载设计、库与约束，执行某个阶段。
  2. 先读日志和报告，确认失败原因或需要优化的指标。
  3. 在 GUI 中打开保存的数据库，查看对应路径、单元、连线或错误标记。
  4. 将改动保存到 RTL、约束或脚本，重新运行并比较结果。

Berkeley 的 Innovus 教程演示了脚本与 GUI 的配合。初次体验开源流程，可以沿 ORFS 教程完成一次 RTL-to-GDS，再分别打开综合、Floorplan、CTS 和 Routing 的结果。先能把每份报告对应到一个设计阶段，再开始调整参数。

Analog / Mixed-Signal 的另一条路径

模拟电路的起点通常是拓扑、器件尺寸和性能指标，主要操作对象是原理图与晶体管级电路：

Specification
    ↓
Schematic & Sizing ↔ SPICE Simulation
    ↓
Layout ↔ DRC / LVS
    ↓
Parasitic Extraction → Post-layout Simulation → Signoff

用 Xschem 画原理图、ngspice 做仿真，可以先学会观察工作点、增益、带宽与瞬态响应；再进入版图、寄生提取和后仿真。商业环境中常见 Cadence Virtuoso / Spectre 和 Synopsys Custom Compiler / PrimeSim。入门推荐 JKU Analog Circuit Design 的第 1、2 章，其中有原理图、仿真示例和工具环境说明；后续章节再深入尺寸设计与 PVT 分析。

Xschem & ngspice · Schematic and Simulation

下图是一个 RLC 瞬态仿真：后方是 Xschem 原理图，前方是 ngspice 波形和控制台。观察节点 A、B、C 的电压如何随时间变化，再回到原理图理解器件与连线。

OpenLane · From RTL to Silicon
