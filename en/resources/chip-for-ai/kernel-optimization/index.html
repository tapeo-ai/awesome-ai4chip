Kernel Optimization

Kernel generation, optimization, evaluation, and compiler tools for GPUs, CPUs, and accelerators.

Generation, Optimization, and Evaluation

  • AccelOpt (2025/2026) — Builds optimization memory from slow-fast kernel pairs to autonomously optimize kernels on AWS Trainium, and provides NKIBench. Paper
  • AKG kernel Agent (2025) — Uses multiple agents to generate, port, and tune kernels across GPUs and NPUs, supporting several kernel DSLs.
  • AscSpMM (2026) — Pipelines sparse indexing and operand preparation on the vector engine with Cube matrix computation on Ascend 910B3, using Vector-CSR, a double-slot ring buffer and adaptive tiling. Paper
  • Atrex Kernel Agent (2026) — Uses a GPU knowledge base, profiling tools, and structured workflows for kernel implementation, diagnosis, and iterative optimization.
  • AutoProfiler (2026) — Learns a deterministic profiling tree from optimization feedback, selecting hardware counters per kernel to inform one LLM kernel rewrite under a fixed measurement budget. Paper
  • AWS Neuron Agentic Development — AWS’s official NKI agent tools cover kernel authoring, compilation repair, profiling, performance analysis, and API migration.
  • BitDecoding-FP4 (2026) — Implements native FP4 KV-cache decoding with dual-residual query quantization, probability scaling, and outlier-aware key quantization; on an NVIDIA B300, peak serving throughput for Qwen3-4B and Qwen3-30B-A3B is 2.4–3.0× BF16 KV, with NVFP4 accuracy within 0.5 points of BF16 KV. Paper
  • CUDA Agent (2026) — Combines large-scale agentic RL, CUDA task data, expert skills, and verifiable execution environments to train high-performance kernel generation. Paper
  • CUDA-L1 (2025/2026) — Optimizes CUDA kernels with contrastive reinforcement learning and execution feedback, discussing performance rewards and reward hacking. Paper
  • ForgeKernel (2026) — Distills reusable hardware mechanisms from measured reference kernels and promotes implementations that pass correctness and performance checks to the next reference; on 27 operators and 29 input configurations on Hopper and Blackwell, 25 configurations match or beat the expert reference, with a 10% geometric-mean gain. Paper
  • KernelBench (2025) — Uses PyTorch tasks to evaluate whether models can generate correct and faster GPU kernels, with execution and measurement tools.
  • KernelMosaic (2026) — Builds diverse CUDA tasks from text, reference implementations and mathematical descriptions, producing execution-verified solutions and agent traces to fine-tune Qwen3.5-9B for kernel generation and tool-feedback refinement.
  • Kevin-32B (2025) — Trains CUDA kernel generation and optimization through multi-turn reinforcement learning, enabling iterative code improvement with execution feedback. Paper Model
  • LARK (2026) — Fixes a GPU machine model and operator semantics in Lean 4, then uses agents to prove segment-wise functional and memory equivalence between generated kernels and PyTorch references under exact arithmetic.
  • MaxKernel (2026) — Provides human-agent collaboration, autonomous optimization, and graph-search modes for TPU kernels, combining compilation, testing, and hardware profiling. Code
  • PyTorch KernelAgent / KernelFalcon (2025–2026) — Organizes kernel generation, numerical validation, hardware profiling, and bottleneck analysis into a multi-agent loop, with shared memory guiding optimization. Technical Blog
  • RNGD Multi-Agent Kernel Optimization (2026) — Builds FuriosaAI RNGD knowledge from checked documentation, microbenchmarks, and compiler legality rules, searches three Gemma decode kernels with Design Trees, and accepts changes through repeated device comparisons. Measurement tools and artifacts
  • Warpline (2026) — Inserts probes into GPU kernel binaries and aligns warp timelines with hardware profiling, so an agent can remeasure after source, IR, or PTX edits without recompiling.
  • ZYFA (2026) — Writes FP8 FlashAttention prefill kernels for the AMD Instinct MI355X, replacing the exponential with a multiply-add and integer conversion and overlapping softmax with matrix multiplication; on attention inputs from three models it reaches 1.16–1.76× the throughput of AITER. Paper

Kernel Libraries and Compilers

  • Arknife (2026) — Expresses mappings between logical tensors and hardware axes with a unified constrained-layout algebra, using global constraint solving and target-instruction descriptions to generate and repair layouts for x86, Hexagon NPUs and NVIDIA GPUs.
  • Arm KleidiAI — An AI micro-kernel library for Arm CPUs, with architecture-optimized matrix operations and data-packing routines. Main Repository
  • DeepEP — Provides high-throughput and low-latency communication paths for MoE expert parallelism, connecting model routing, GPU kernels, and network transport.
  • oneDNN — Provides optimized deep-learning primitives and hardware-specific kernels; AMD and Intel announced plans to integrate ZenDNN optimizations into oneDNN as a common PyTorch acceleration path for x86 CPUs. Integration announcement
  • TauLang (2026) — A kernel language and compiler for statically scheduled accelerators that makes issue cycles program parameters and jointly solves tensor placement and cycle scheduling with integer linear programming.
  • TileLang — Expresses GPU, CPU, and accelerator kernels through tiles to simplify low-level optimization and implementation across hardware backends.
  • TLX (Triton Low-Level Extensions) (2026) — Exposes warp-group execution, asynchronous data movement and synchronization in Triton; Meta describes production use in recommendation, inference and LLM pretraining and co-design across models, runtimes and kernels.
  • Triton — A language and compiler for high-performance GPU kernels, used as a code-generation target by multiple kernel agents.
